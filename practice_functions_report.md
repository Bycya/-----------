Освоить создание пользовательских функций PostgreSQL, применение языка PL/pgSQL и использование функций для упрощения операций с данными туристической фирмы.

В работе используются таблицы базы данных `tourism_firm`, созданной в первом семестре.

Исполняемый SQL-скрипт находится в файле:

```text

```

Скрипт создаёт четыре функции:

1. `calculate_booking_cost` — рассчитывает полную стоимость бронирования.
2. `get_tour_catalog_by_country` — формирует каталог туров с помощью курсора.
3. `register_booking_payment` — безопасно регистрирует платёж.
4. `apply_group_discounts` — назначает скидки групповым бронированиям в цикле.

## 1. Использованные возможности PL/pgSQL

| Возможность | Где используется |
|---|---|
| Переменные | Во всех четырёх функциях |
| Ветвление `IF / ELSIF / ELSE` | Проверка параметров, определение категории цены, назначение скидок |
| Цикл `LOOP` | Обработка строк курсора в `get_tour_catalog_by_country` |
| Цикл `FOR` | Последовательная обработка бронирований в `apply_group_discounts` |
| Явный курсор | `get_tour_catalog_by_country` |
| `FETCH` и `EXIT WHEN NOT FOUND` | Чтение строк курсора |
| `CONTINUE` | Пропуск отменённых бронирований |
| `SELECT INTO` | Получение значений из таблиц в локальные переменные |
| `GET DIAGNOSTICS` | Получение числа изменённых строк после `UPDATE` |
| Исключения `RAISE EXCEPTION` | Проверка параметров и бизнес-ограничений |
| Раздел `EXCEPTION` | Обработка отсутствующего бронирования |
| Блокировка `FOR UPDATE` | Защита регистрации платежей от параллельных изменений |
| Возврат таблицы | Каталог туров `RETURNS TABLE` |

## 2. Функция расчёта стоимости бронирования

### Назначение

Функция получает идентификатор бронирования и рассчитывает итоговую стоимость:

```text
цена тура × количество человек × (1 − скидка / 100)
```

Сигнатура:

```sql
calculate_booking_cost(p_booking_id BIGINT)
RETURNS NUMERIC
```

Основные действия функции:

1. Проверяет, что идентификатор является положительным числом.
2. Получает цену, количество человек и скидку через `SELECT INTO`.
3. Проверяет специальную переменную состояния `FOUND`.
4. Вызывает исключение, если бронирование не существует.
5. Рассчитывает и возвращает итоговую стоимость.

Локальные переменные:

```sql
DECLARE
    v_price      NUMERIC(12, 2);
    v_people     INTEGER;
    v_discount   NUMERIC(5, 2);
    v_total_cost NUMERIC(12, 2);
```

Проверка отсутствующего бронирования:

```sql
IF NOT FOUND THEN
    RAISE EXCEPTION
        'Бронирование с идентификатором % не найдено',
        p_booking_id
        USING ERRCODE = 'P0002';
END IF;
```

Функция объявлена как `STABLE`, поскольку она читает данные, но самостоятельно их не изменяет.

### Проверка

```sql
SELECT public.calculate_booking_cost(1);
```

Проверка исключения:

```sql
SELECT public.calculate_booking_cost(999999999);
```

Ожидается сообщение:

```text
ERROR: Бронирование с идентификатором 999999999 не найдено
```

Проверка неправильного параметра:

```sql
SELECT public.calculate_booking_cost(-1);
```

## 3. Курсорная функция каталога туров

### Назначение

Функция возвращает каталог туров для указанной страны. Если параметр равен `NULL`, возвращаются туры всех стран.

Сигнатура:

```sql
get_tour_catalog_by_country(p_country TEXT DEFAULT NULL)
RETURNS TABLE (...)
```

Функция использует параметризованный явный курсор:

```sql
c_tours CURSOR (v_country TEXT) FOR
    SELECT ...
    FROM tours AS t
    JOIN destinations AS d
        ON d.destination_id = t.destination_id
    WHERE v_country IS NULL
       OR LOWER(d.country) = LOWER(v_country);
```

Курсор открывается командой:

```sql
OPEN c_tours(p_country);
```

Строки курсора обрабатываются в цикле:

```sql
LOOP
    FETCH c_tours INTO r_tour;
    EXIT WHEN NOT FOUND;

    ...

    RETURN NEXT;
END LOOP;
```

Для каждого тура определяется ценовая категория:

```sql
IF r_tour.price < 100000 THEN
    price_category := 'бюджетный';
ELSIF r_tour.price <= 200000 THEN
    price_category := 'средний';
ELSE
    price_category := 'премиальный';
END IF;
```

После завершения обработки курсор закрывается:

```sql
CLOSE c_tours;
```

### Проверка

Туры одной страны:

```sql
SELECT *
FROM public.get_tour_catalog_by_country('Россия');
```

Все туры:

```sql
SELECT *
FROM public.get_tour_catalog_by_country(NULL);
```

Фильтрация результата функции:

```sql
SELECT *
FROM public.get_tour_catalog_by_country(NULL)
WHERE price_category = 'бюджетный'
ORDER BY price;
```

## 4. Функция регистрации платежа

### Назначение

Функция безопасно добавляет успешный платёж по бронированию.

Сигнатура:

```sql
register_booking_payment(
    p_booking_id BIGINT,
    p_amount NUMERIC,
    p_payment_method TEXT
)
RETURNS BIGINT
```

Функция выполняет следующие проверки:

- сумма больше нуля;
- способ оплаты равен `cash`, `card` или `bank_transfer`;
- бронирование существует;
- новый платёж вместе с уже оплаченными суммами не превышает стоимость бронирования.

Строка бронирования блокируется до завершения транзакции:

```sql
SELECT ...
INTO STRICT v_total_cost
FROM bookings AS b
JOIN tours AS t
    ON t.tour_id = b.tour_id
WHERE b.booking_id = p_booking_id
FOR UPDATE OF b;
```

Блокировка предотвращает одновременную регистрацию двух платежей на один остаток разными транзакциями.

Сумма ранее проведённых платежей рассчитывается агрегатной функцией:

```sql
SELECT COALESCE(
    SUM(amount) FILTER (WHERE status = 'paid'),
    0
)
INTO v_paid_amount
FROM payments
WHERE booking_id = p_booking_id;
```

При переплате вызывается исключение:

```sql
IF v_paid_amount + p_amount > v_total_cost THEN
    RAISE EXCEPTION ...
        USING ERRCODE = '23514';
END IF;
```

Отсутствие бронирования обрабатывается в разделе `EXCEPTION`:

```sql
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        RAISE EXCEPTION
            'Бронирование с идентификатором % не найдено',
            p_booking_id;
```

Функция объявлена как `VOLATILE`, потому что она добавляет данные в таблицу `payments`.

### Проверка успешного платежа

Для демонстрации используется транзакция с откатом:

```sql
BEGIN;

SELECT public.register_booking_payment(
    5,
    1000.00,
    'card'
) AS new_payment_id;

SELECT *
FROM payments
WHERE booking_id = 5
ORDER BY payment_id;

ROLLBACK;
```

Если бронирование №5 уже полностью оплачено, следует выбрать другое бронирование с положительным остатком.

### Проверка исключения при переплате

```sql
BEGIN;

SELECT public.register_booking_payment(
    1,
    999999999.00,
    'card'
);
```

Ожидается ошибка о превышении остатка. После ошибки:

```sql
ROLLBACK;
```

### Проверка способа оплаты

```sql
SELECT public.register_booking_payment(
    5,
    1000.00,
    'cryptocurrency'
);
```

Функция должна отклонить недопустимый способ оплаты.

## 5. Функция группового назначения скидок

### Назначение

Функция последовательно просматривает бронирования и назначает заданную скидку, если:

- бронирование не отменено;
- количество человек не меньше заданного значения;
- существующая скидка меньше новой.

Сигнатура:

```sql
apply_group_discounts(
    p_min_people INTEGER DEFAULT 3,
    p_discount NUMERIC DEFAULT 10
)
RETURNS INTEGER
```

Переменная-счётчик инициализируется при объявлении:

```sql
v_total_updated INTEGER := 0;
```

Бронирования обрабатываются циклом `FOR`:

```sql
FOR r_booking IN
    SELECT ...
    FROM bookings
    ORDER BY booking_id
LOOP
    ...
END LOOP;
```

Отменённые бронирования пропускаются:

```sql
IF r_booking.status = 'cancelled' THEN
    CONTINUE;
END IF;
```

Количество строк, изменённых текущим `UPDATE`, получается через:

```sql
GET DIAGNOSTICS
    v_changed_in_iteration = ROW_COUNT;
```

### Проверка

```sql
BEGIN;

SELECT public.apply_group_discounts(
    3,
    10
) AS updated_bookings;

SELECT
    booking_id,
    number_of_people,
    status,
    discount
FROM bookings
WHERE number_of_people >= 3
ORDER BY booking_id;

ROLLBACK;
```

После `ROLLBACK` тестовые изменения скидок отменяются.

Проверка некорректной скидки:

```sql
SELECT public.apply_group_discounts(3, 150);
```

Ожидается исключение о допустимом диапазоне от 0 до 100.


Функции, изменяющие данные, рекомендуется проверять внутри транзакции:

```sql

-- Проверка результата.

FROM bookings
ORDER BY booking_id;

```

### Шаг 5. Работа после исключения

Если функция вызвала исключение внутри явной транзакции, транзакция переходит в состояние ошибки. Перед следующим запросом нужно выполнить:

```sql
ROLLBACK;
```

После этого можно начинать новый тест.

## 8. Преимущества функций перед представлениями

### 8.1. Параметры

Представление не принимает параметры. Для него условия задаются во внешнем запросе:

```sql
SELECT *
FROM v_tour_catalog
WHERE country = 'Россия';
```

Функция может принимать параметры непосредственно:

```sql
SELECT *
FROM get_tour_catalog_by_country('Россия');
```

### 8.2. Процедурная логика

Представление является сохранённым запросом и не поддерживает полноценные циклы, курсоры и процедурные ветвления.

PL/pgSQL-функция поддерживает:

- `IF`, `ELSIF`, `ELSE`;
- `LOOP`, `WHILE`, `FOR`;
- курсоры;
- локальные переменные;
- обработку исключений;
- динамический SQL.

### 8.3. Изменение нескольких объектов

Функция может выполнять несколько взаимосвязанных операций `INSERT`, `UPDATE` и `DELETE`. Все операции входят в одну транзакцию: либо выполняются полностью, либо полностью откатываются.

Представление само по себе предназначено прежде всего для чтения. Простые представления могут быть автоматически изменяемыми, но сложным многотабличным представлениям требуются триггеры.

### 8.4. Проверка бизнес-правил

Функция может проверить параметры и текущее состояние базы перед изменением данных:

```sql
IF v_paid_amount + p_amount > v_total_cost THEN
    RAISE EXCEPTION ...;
END IF;
```

Представление не предоставляет аналогичного процедурного механизма проверки.

### 8.5. Исключения

Функции позволяют выдавать понятные сообщения и SQLSTATE:

```sql
RAISE EXCEPTION
    'Сумма платежа должна быть больше нуля'
    USING ERRCODE = '22023';
```

Это упрощает диагностику ошибок приложением и пользователем.

### 8.6. Снижение количества обращений к серверу

Несколько вычислений и изменений можно выполнить одним вызовом функции. Без функции приложению пришлось бы отправлять несколько запросов и самостоятельно координировать их результаты.

### 8.7. Повторное использование

Логика хранится централизованно в базе. Её могут использовать pgAdmin, консольный клиент, веб-приложение и другие программы без дублирования SQL-кода.

### 8.8. Управление доступом

Пользователю можно выдать право `EXECUTE` на функцию, не предоставляя прямой доступ к базовым таблицам. Для контролируемого выполнения с правами владельца применяется `SECURITY DEFINER`.

## 9. Когда представления удобнее функций

Функции не являются полной заменой представлений.

Представления удобнее, когда требуется:

- сохранить простой декларативный запрос;
- обращаться к результату как к обычной таблице;
- ограничить перечень доступных строк и столбцов;
- позволить оптимизатору встроить запрос представления в общий план;
- не требуется процедурная логика или параметры.

Функции и представления дополняют друг друга: представления удобны для безопасного и понятного доступа к данным, а функции — для вычислений, проверок и сложных операций.
